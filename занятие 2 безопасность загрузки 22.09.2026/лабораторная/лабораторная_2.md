# РАБОТА 1. Защита загрузчика GRUB2

**Цель:** изучить атаку на процесс загрузки через параметры ядра и настроить аутентификацию в GRUB2.

**Краткая теория.** GRUB2 перед загрузкой ядра показывает меню, в котором клавишей `e` можно отредактировать пункт: в строке `linux` дописывают `init=/bin/bash`, и система стартует с root‑оболочкой без аутентификации. Защита строится на механизме `superusers`: при заданном списке суперпользователей редактирование пунктов и консоль GRUB доступны только по логину и паролю (пароль хранится в виде хеша PBKDF2), а штатная загрузка оставляется открытой через флаг `--unrestricted`.

## Шаг 0. Подготовка

Выполните и запишите результат:

```bash
grub-install --version
[ -d /sys/firmware/efi ] && echo "Режим загрузки: UEFI" || echo "Режим загрузки: BIOS/Legacy"
```

Ожидаемый результат: выведена версия GRUB 2.x и режим загрузки.

## Шаг 1. Демонстрация атаки (до защиты)

1.1. Перезагрузите ВМ. В меню GRUB нажмите клавишу `e` на пункте Debian.
1.2. В строке, начинающейся с `linux`, допишите в конец `init=/bin/bash` и нажмите `Ctrl+X` (или `F10`).
1.3. В открывшейся оболочке выполните `id` и `mount | grep ' / '`.

**Скриншот 1.1 — root‑оболочка без аутентификации: виден вывод `id` (uid=0) и монтирование корня.**


1.4. Перезагрузите ВМ принудительно (сброс ВМ или `exec /sbin/reboot -f`).

## Шаг 2. Настройка аутентификации GRUB2

2.1. Сгенерируйте хеш пароля:

```bash
grub-mkpasswd-pbkdf2
```

Введите пароль дважды (запишите его, он понадобится далее).

> **Важно.** Хеш `grub.pbkdf2.sha512.…` индивидуален: он зависит от случайной соли,
> поэтому у каждого студента получается свой. Скриншот с хешем обязателен — по нему
> проверяется самостоятельность выполнения работы.

**Скриншот 1.2 — вывод `grub-mkpasswd-pbkdf2` с хешем `grub.pbkdf2.sha512.…` (виден полностью).**

```
┌────────────────────────────────────────────────────────┐
│                                                        │
│              МЕСТО ДЛЯ СКРИНШОТА 1.2                    │
│                                                        │
└────────────────────────────────────────────────────────┘
```

2.2. Запишите настройку суперпользователя в `/etc/grub.d/40_custom` (вместо `grub.pbkdf2…` вставьте свой хеш из п. 2.1):

```bash
sudo nano /etc/grub.d/40_custom
```

Содержимое файла (после служебных строк `#!/bin/sh` и `exec tail -n +3 $0`):

```text
set superusers="admin"
password_pbkdf2 admin grub.pbkdf2.sha512.10000.ВАШ_ХЕШ
```

2.3. Разрешите штатную загрузку без пароля, но запретите редактирование: в файле `/etc/grub.d/10_linux` найдите строки, начинающиеся с `menuentry "`, и добавьте флаг `--unrestricted` после слова `menuentry`:

```bash
sudo sed -i 's/menuentry "/menuentry --unrestricted "/' /etc/grub.d/10_linux
```

Дополнительно (рекомендуется) отключите recovery‑пункты в `/etc/default/grub`: `GRUB_DISABLE_RECOVERY=true`.

2.4. Пересоберите конфигурацию загрузчика:

```bash
sudo update-grub
```

2.5. Перезагрузите ВМ.

# РАБОТА 4. UEFI Secure Boot и подписи модулей ядра (по желанию)

> **По желанию.** Работа 4 выполняется по желанию. Обязательной для отчёта является работа 1.

**Цель:** изучить цепочку доверия UEFI Secure Boot, проверить подписи компонентов и зарегистрировать собственный ключ MOK для подписи модуля ядра.

**Требования к ВМ:** прошивка UEFI и включённый Secure Boot (VMware: Settings → Options → Advanced → Firmware UEFI + флажок Secure Boot; VirtualBox 7: Система → Материнская плата → EFI и включённый Secure Boot; QEMU: OVMF с secboot). Debian 13 загружается с Secure Boot из коробки: shim, GRUB и ядро подписаны.

**Краткая теория.** Secure Boot разрешает выполнение только компонентов, подписанных ключами из баз прошивки (PK/KEK/db). Debian использует загрузчик `shim`, подписанный ключом Microsoft UEFI CA; собственные ключи добавляются через механизм MOK (Machine Owner Key). При включённом Secure Boot ядро находится в режиме lockdown: неподписанные модули не загружаются.

## Шаг 0. Подготовка

Установите пакеты:

```bash
sudo apt update
sudo apt install mokutil sbsigntool build-essential linux-headers-$(uname -r)
```

## Шаг 1. Статус Secure Boot и подписи ядра

1.1. Проверьте состояние:

```bash

sudo dmesg | grep -iE 'secure boot|lockdown'
```

Ожидаемый результат: `SecureBoot enabled`; в dmesg — сообщение о режиме lockdown.

**Скриншот 4.1 — вывод `mokutil --sb-state` (Secure Boot включён) и строка о lockdown.**

## Шаг 2. Неподписанный модуль отклоняется

2.1. Создайте рабочий каталог и файл модуля `hello.c`:

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>

static int __init hello_init(void)
{
    pr_info("Hello, Secure Boot! Modul zagruzhen.\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Modul vygruzhen.\n");
}

module_init(hello_init);
module_exit(hello_exit);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Lab module for Secure Boot");
MODULE_AUTHOR("Student");
```

2.2. Создайте `Makefile` (отступы перед `$(MAKE)` — строго символом Tab):

```make
obj-m += hello.o
KDIR ?= /lib/modules/$(shell uname -r)/build
all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules
clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean
```

2.3. Соберите и попробуйте загрузить неподписанный модуль:

```bash
make
sudo insmod hello.ko
```

Ожидаемый результат: ошибка `insmod: ERROR: … Required key not available`.

**Скриншот 4.2 — ошибка `insmod` (Required key not available) после сборки модуля.**

```

│              МЕСТО ДЛЯ СКРИНШОТА 4.2                    │
│                                                        │
```

## Шаг 3. Создание собственного ключа MOK и подпись модуля

3.1. Сгенерируйте ключевую пару (сертификат в формате DER):

```bash
openssl req -new -x509 -newkey rsa:2048 \
  -keyout MOK.priv -outform DER -out MOK.der \
  -nodes -days 36500 -subj "/CN=Student MOK/"
ls -l MOK.priv MOK.der
```

3.2. Подпишите модуль своим ключом и проверьте подпись:

```bash
sudo /lib/modules/$(uname -r)/build/scripts/sign-file sha256 MOK.priv MOK.der hello.ko
modinfo hello.ko | grep -E 'sig_id|signer|description'
```

**Скриншот 4.3 — вывод `modinfo`: видны `signer: Student MOK` и `sig_id`.**

```
┌────────────────────────────────────────────────────────┐
│                                                        │
│              МЕСТО ДЛЯ СКРИНШОТА 4.3                    │
│                                                        │
└────────────────────────────────────────────────────────┘
```

## Шаг 4. Регистрация ключа MOK в прошивке

4.1. Импортируйте сертификат (задайте пароль MOK):

```bash
sudo mokutil --import MOK.der
```

4.2. Перезагрузите ВМ. На старте появится синее меню **Perform MOK management**: выберите `Enroll MOK` → `Continue` → `Yes` → введите пароль MOK → `Reboot`.

4.3. После загрузки проверьте, что ключ зарегистрирован:

```bash
mokutil --list-enrolled | grep -B2 -A2 'Student MOK'
```

**Скриншот 4.4 — вывод `mokutil --list-enrolled` с вашим сертификатом (CN=Student MOK).**
